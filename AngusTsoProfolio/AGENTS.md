## General Rules
- Inspect Existing code before making changes.
- Prefer small and focused changes
- Preserve the existing architeture unless there is clear reason to change it
- Do not introduce new dependencies unless necessary.
- Reuse existing components and styles when possible.
- Do not remove existing functionality without approval.
- Do not invent personal experience, technologies, metrics, achievements, or other factual claims.
- Keep the site responsive for desktop and mobile
- Keep changes easy to review.

## AI Workflow

For non-trivial changes:

1. Inspect the relevant files.
2. Explain the proposed approach.
3. Wait for approval before making significant changes.
4. Implement the change.
5. Run available lint/build checks.
6. Review the resulting diff.
7. Explain any important tradeoffs or remaining issues.

## Human Ownership

The human makes the final decision about:

- portfolio content
- factual claims
- design direction
- architecture
- dependencies
- final code changes
